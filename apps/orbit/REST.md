# 安静・非装着判定 v0.117 温度判定版

時計を外した直後の動きと温度変化を検出します。昼寝と夜間睡眠に同じ条件を適用します。安静度0〜5はv0.116と同じ5分間の加速度ピーク積算です。

## 装着状態を切り替える条件

- 各秒の3軸加速度の平均と揺れのRMSを集計します。直近10秒のうち9秒以上が有効で、8割以上の秒の揺れと、平均姿勢の変動が設定範囲内に戻ったとき、動作後の静止を検出します。60秒窓には54秒以上の記録が必要です。既定の揺れ上限は0.030 g、姿勢変動上限は0.025 gです。
- 気圧センサーの温度を通常5分ごとに測り、動き始めにも直前の測定から1分以上経っていれば1回測ります。置く・持ち上げる動作の直後は約10秒ごとに最大2分間取得します。安定するまでの遅い熱応答は最長12分追跡します。低頻度の測定で変化が現れた場合は短く再測定します。
- 動作前15分以内の温度から直線の傾きと残差のRMSを求めます。1分以上離れた測定点が足りない場合は平らな基準を使います。動作前の傾向を推定でき、静止に移る前90秒以内の実測値があればそれを起点にし、最初の静止時の測定までに温度が急変した場合も評価します。該当する測定がない場合は静止後の最初の3点の中央値を起点とします。実際の温度変化量と、動作前の傾向から予測した温度との差を求めます。両方が同方向に下限を超え、当てはめた傾きも同方向であることを確認します。下限は **Temp change（初期0.20℃）** と基準残差RMSの3倍の大きい方です。温度変化率の固定閾値ではありません。30秒以上にわたる4点以上の観測と、連続2回の一致を要求します。
- 置いた後の静止が10秒窓と60秒窓の両方で確認でき、温度条件がそろい、30秒以上の心拍測定を完了した場合に非装着を判定します。高信頼の秒がゼロの場合と、20秒以上の心拍イベントが得られ高信頼の割合が設定値（初期10%）以下の場合が対象です。心拍電源エラーは別に記録します。
- 1秒の心拍はその秒の最後の信号で評価します。BPMが正で信頼度が設定値（初期90%）を超えた秒が10秒以上、心拍観測秒の6割以上あり、直近10秒にも有効な脈があると装着を確認します。着脱動作後はその動作以降の脈を使います。
- 寝返りや温度欠測だけでは既知の装着を解除しません。非装着が確認できている時計は、温度が落ち着いた後や一度裏返した後も静止中の非装着を保持します。持ち上げた後は心拍の再検出、または持続した動きと温度応答で装着を確認します。長い動きで着脱が分からなくなった区間は再評価します。
- 充電開始で非装着が確定します。外した直後も非装着を引き継ぎ、余熱を避けるため10分間は温度を判定対象から外します。この間も有効な心拍で装着に戻れます。
- 最近の装着状態は通常の5分保存・終了時に履歴と一緒に保存します。再開までに6分を超える観測の空白があれば、現在の装着状態を再確認します。

## 表示と設定

現在の非装着は白い2ピクセルの点で表示します。表示中の時計には状態が変わったときに反映します。完成した5分枠は、加速度を270秒以上観測し、その半分以上かつ60秒以上で非装着を観測した場合に白い点になります。充電中は赤い充電率の棒に同じ白点を重ねます。温度が腕と置き面で近いときや起動時から卓上にあるときは、温度による着脱の識別ができないことがあります。確証を得るまでは安静度の計算を続けます。

**Rest graph → Non-wear → Temp change** で温度変化量の下限を変更できます。共通プロファイルは `orbit.restcfg.json`、キーは `restTempDeltaC` です。以前の時刻設定は装着判定に使用しません。Rest Labの新しい記録には `restThermalVersion:1` を付けます。温度を含まない既存CSVから実機の熱応答は検証できません。温度閾値と検出時間は、緩いバンドでの装着と、材質・温度の異なる面への静置での検証対象です。

## 安静度0〜5の目安

| 安静度 | 活動の目安 | 300秒換算のピーク積算量P | 棒の長さ |
|---|---|---|---|
| 5 | 夜の睡眠相当 | P < 0.1 | 最大 |
| 4 | 昼間の居眠り、机に腕を平らに乗せる状態 | 0.1 ≦ P < 3 | 最大の4/5 |
| 3 | 集中したデスクワーク相当 | 3 ≦ P < 60 | 最大の3/5 |
| 2 | 日常生活活動相当 | 60 ≦ P < 200 | 最大の2/5 |
| 1 | 歩行・階段登り相当 | 200 ≦ P < 500 | 最大の1/5 |
| 0 | 走行・運動相当 | 500 ≦ P | 0 |

段階名は動きの少なさ／多さの目安です。夜間という条件だけで5にしたり、昼間の睡眠を確定したりする処理はありません。加速度のみでは腕を動かさず起きている状態と睡眠を確実に区別できません。睡眠・居眠り・走行のラベル付き実測記録がないため、特に上位2段階と新しい歩行／走行境界500は追加の検証が必要です。非装着はこの0〜5と別に判定します。

設定の境界は5本で、`restActivityT5` が新しい歩行／走行境界です。最初の4本の設定は維持し、5本目がなければ500（既存の4本目が500以上ならその値より1大きい値）を追加します。`restScaleVersion:6` は6段階の尺度を示し、非装着アルゴリズムの版とは独立です。

履歴形式v5では安静0〜5を0/20/40/60/80/100で保存します。旧v2〜v4履歴は棒の長さが変わらないよう旧1〜5を対応する新コードへ移します。過去に走行していたかを再判定することはできません。旧CSVのグラフも当時の1〜5として読み、新CSVは0〜5として表示します。


## v0.116 省電力化

- 初回に `restPowerVersion:1` を保存し、既存設定も5Hz処理（Eco sampling）へ移行します。その後にユーザーがFullへ変更した場合は保持します。加速度センサー自体のイベント周期は変えず、アプリ内で200msの位相固定スロットへ間引きます。他アプリの測定周期には触れません。
- 5Hzではピーク積算量が変化するため、300秒換算後に経験的な補正係数1.65を掛け、既存の段階境界を使います。Full処理時は補正しません。3記録の再生では装着中の確定11枠の段階（1が1枠、2が3枠、3が7枠）を維持しました。未知の活動や走行に対する同等性は保証できません。
- 非装着判定後はピーク用HPF・ピーク積算を休止します。60秒窓の監視は継続し、窓の非装着判定が崩れるか、休止開始姿勢から0.15g以上（通常の揺れ閾値の5倍が大きければその値）の3軸差を検出したサンプルから通常処理へ戻ります。直前のサンプルでフィルターを初期化し、復帰サンプルを入力します。再休止まで10秒待ちます。
- 加速度の観測時間とピーク積算が動いていた時間を別々に記録します。積算休止中の時間を安静0／5として埋めません。非装着の多数決を満たさず、ピーク観測が270秒未満の混在枠は `activity_partial`（未確定）です。5分境界でも休止状態は維持します。データ欠落や再起動では監視状態を再確認します。
- 旧5分最大3D driftと旧保持処理を廃止しました。新しい診断の `drift_g` は60秒窓のPose RMSです。Rest Labのraw開始設定に `restPowerVersion` を含め、グラフで旧指標と区別します。
- 非装着窓の判定とHRM開始条件の確認は10秒ごとにまとめます。HRM終了タイマー・充電イベント・ピーク休止からの復帰監視は継続します。

充電中は5分ごとの通常描画を維持し、その間の毎分更新では現在の充電棒付近の小さな背景画像を復元して棒・時刻・重なる文字を描き直します。地球／月の再計算は行いません。画像の切り出しが使える2v26以降で有効にし、旧版・メモリ不足・画像取得失敗時は全体描画へ戻ります。実装は[Graphics.asImageの公式仕様](https://www.espruino.com/ReferenceBANGLEJS2#l_Graphics_asImage)に基づき、取得画像の寸法も検証します。日の出・日の入りのBMP保存は従来どおり完全描画後に行います。

電池消費の実測はまだありません。5Hzによるサンプル数削減やピーク計算休止はCPU処理の削減であり、そのまま同じ割合の電池削減を意味しません。

### v0.119 診断CSV

Rest graph → Debug CSV は標準でオンです。自用アップローダーの My Apps → tenkyu → Download data from app から日付別CSVを保存できます。時刻・ファイルの日付はUTCで、日本時間は9時間を足します。5分枠の加速度ピーク積算値と補正値、末尾の判定窓の姿勢・振動・温度・心拍、適用閾値、非装着と判定した秒数、結果と理由を記録します。温度の測定時刻はUnixミリ秒です。空欄は測定値なし、心拍信頼度の -1 は未取得です。結果コードは0～100が安静度×20、101～201が充電率+101、253が心拍エラー、254が非装着、255が欠測です。センサーの追加起動はありません。最大3ファイル、各128 KiBで、空きが68 KiB未満なら記録を休止します。書き込み状態は Last check → Debug CSV に表示します。履歴の再読込にも失敗すると元の履歴を保護し、その間の判定を独立CSVに記録します。履歴は次のサービス起動時に再確認します。

# 安静・非装着判定（v0.116）

安静度は従来の5分間の3軸HPFピーク超過量積算で計算します。ピーク閾値のデフォルトは0.003g、段階境界は0.1 / 3 / 60 / 200 / 500です。積算量の単位はgで、単一サンプルの加速度とは異なります。270秒以上の観測を300秒相当に補正します。

非装着は安静度の段階や積算量に依存させず、直近60秒窓を10秒ごとに評価します。各秒の平均XYZと、平均からの3軸偏差RMSを集計します。各秒は3点以上かつサンプル時間幅0.5秒以上必要で、60秒中54秒以上を要求します。5HzのEco samplingでも条件は同じです。新しいセンサー周期設定は行いません。

- 通常の静止条件：各秒の揺れRMSの中央値≦0.030g、秒平均XYZの窓内変動RMS≦0.025g。
- 非常に静かな条件：両RMS≦0.012g。高信頼度の脈あり秒が60秒中2秒以下なら、心拍イベントが届かなくても非装着と推定します。
- 通常の静止条件では、心拍イベントを観測した秒が20秒以上、かつ脈あり秒の割合≦10%で非装着と推定します。
- 脈あり秒は、その秒の最後のイベントでBPM>0かつ信頼度>90%（変更可）となった秒です。1イベントだけで装着とはしません。脈あり10秒以上かつ割合≧60%で装着を確認します。
- 「Keep until move」がオンなら、確認済みの装着／非装着は静止条件が崩れるまで保持します。データ不足、充電状態変化、実際のHRM電源エラーでは保持を解除します。HRM電源エラーは非装着と区別します。

従来の「3D drift」は5分枠の開始姿勢からの最大差であり、新しい「Pose RMS」とは違う指標です。旧キー `restWearThreshold` は設定ファイル内に残しても、新しい判定には使いません。

## 省電力と欠測

既存の他アプリの心拍イベントを再利用します。心拍での確認が必要な静止状態だけで、原則30秒（30〜60秒設定可）のプローブを開始します。判定できれば途中で終了し、このアプリ自身のHRM電源要求だけを解放します。欠測・判定保留は1分後、その後は15分後の再試行とし、動き・充電・終了時にもプローブを停止します。非常に静かな非装着状態や、保持中の装着／非装着では追加のプローブを開始しません。

心拍イベントがないことだけで非装着にはしません。例外は上記の非常に静かな加速度条件を満たす場合です。これは加速度による推定で、腕に装着したまま完全に静止する場合の誤判定を完全には除けません。HRMの電源が実際にオンにならない場合は測定失敗として扱います。

## 表示と履歴

非装着の確定5分枠は、観測時間の半分以上かつ60秒以上が非装着判定だった枠です。枠の末尾の状態だけで5分全体を塗り替えません。直近窓が非装着なら現在位置にも白い2ピクセルの点を描きます。充電中は従来の赤い棒と安静5先端位置の白い点です。途中の裏返し操作は一時的な動きとして扱い、その後の60秒窓で再判定します。

v2〜v4の完成済み履歴は表示を維持し、過去の判定は再計算しません。旧アルゴリズムの未完了枠の内部状態は持ち越しません。初回は60秒の判定準備期間、5分履歴には270秒の観測要件があります。

## 設定と移行

初回起動時に移行印 `restAlgorithmVersion:4` を保存します。既知の旧初期値（0.5/2/6/18、1/2/6/18、0.1/3/20/200）の境界は0.1/3/60/200に移行します。その他の独自境界値は維持します。旧15秒プローブは30秒に移行します。

変更できる新キー：`restWearNoiseG:0.030`、`restWearDriftG:0.025`、`restQuietNoiseG:0.012`、`restQuietDriftG:0.012`、`restAbsentRatio:0.10`。Rest Labとtenkyuで同じ `orbit.restcfg.json` を共用でき、tenkyuのRest graph → Import test profileで取り込めます。

3回の実測記録による再生試験では、卓上の表・裏を判定し、装着中の記録では非装着を出さず、安静度が1〜3になりました。前回の揺れが大きい静置記録も心拍条件を使って判定しました。閾値を選んだ同じデータによる確認であり、未知条件に対する識別精度や消費電力の実測値ではありません。


## 安静度0〜5の目安

| 安静度 | 活動の目安 | 300秒換算のピーク積算量P | 棒の長さ |
|---|---|---|---|
| 5 | 夜の睡眠相当 | P < 0.1 | 最大 |
| 4 | 昼間の居眠り、机に腕を平らに乗せる状態 | 0.1 ≦ P < 3 | 最大の4/5 |
| 3 | 集中したデスクワーク相当 | 3 ≦ P < 60 | 最大の3/5 |
| 2 | 日常生活活動相当 | 60 ≦ P < 200 | 最大の2/5 |
| 1 | 歩行・階段登り相当 | 200 ≦ P < 500 | 最大の1/5 |
| 0 | 走行・運動相当 | 500 ≦ P | 0 |

段階名は動きの少なさ／多さの目安です。夜間という条件だけで5にしたり、昼間の睡眠を確定したりする処理はありません。加速度のみでは腕を動かさず起きている状態と睡眠を確実に区別できません。睡眠・居眠り・走行のラベル付き実測記録がないため、特に上位2段階と新しい歩行／走行境界500は追加の検証が必要です。非装着はこの0〜5と別に判定します。

設定の境界は5本で、`restActivityT5` が新しい歩行／走行境界です。最初の4本の設定は維持し、5本目がなければ500（既存の4本目が500以上ならその値より1大きい値）を追加します。`restScaleVersion:6` は6段階の尺度を示し、非装着アルゴリズムの版とは独立です。

履歴形式v5では安静0〜5を0/20/40/60/80/100で保存します。旧v2〜v4履歴は棒の長さが変わらないよう旧1〜5を対応する新コードへ移します。過去に走行していたかを再判定することはできません。旧CSVのグラフも当時の1〜5として読み、新CSVは0〜5として表示します。


## v0.116 省電力化

- 初回に `restPowerVersion:1` を保存し、既存設定も5Hz処理（Eco sampling）へ移行します。その後にユーザーがFullへ変更した場合は保持します。加速度センサー自体のイベント周期は変えず、アプリ内で200msの位相固定スロットへ間引きます。他アプリの測定周期には触れません。
- 5Hzではピーク積算量が変化するため、300秒換算後に経験的な補正係数1.65を掛け、既存の段階境界を使います。Full処理時は補正しません。3記録の再生では装着中の確定11枠の段階（1が1枠、2が3枠、3が7枠）を維持しました。未知の活動や走行に対する同等性は保証できません。
- 非装着判定後はピーク用HPF・ピーク積算を休止します。60秒窓の監視は継続し、窓の非装着判定が崩れるか、休止開始姿勢から0.15g以上（通常の揺れ閾値の5倍が大きければその値）の3軸差を検出したサンプルから通常処理へ戻ります。直前のサンプルでフィルターを初期化し、復帰サンプルを入力します。再休止まで10秒待ちます。
- 加速度の観測時間とピーク積算が動いていた時間を別々に記録します。積算休止中の時間を安静0／5として埋めません。非装着の多数決を満たさず、ピーク観測が270秒未満の混在枠は `activity_partial`（未確定）です。5分境界でも休止状態は維持します。データ欠落や再起動では監視状態を再確認します。
- 旧5分最大3D driftと旧保持処理を廃止しました。新しい診断の `drift_g` は60秒窓のPose RMSです。Rest Labのraw開始設定に `restPowerVersion` を含め、グラフで旧指標と区別します。
- 非装着窓の判定とHRM開始条件の確認は10秒ごとにまとめます。HRM終了タイマー・充電イベント・ピーク休止からの復帰監視は継続します。

充電中は5分ごとの通常描画を維持し、その間の毎分更新では現在の充電棒付近の小さな背景画像を復元して棒・時刻・重なる文字を描き直します。地球／月の再計算は行いません。画像の切り出しが使える2v26以降で有効にし、旧版・メモリ不足・画像取得失敗時は全体描画へ戻ります。実装は[Graphics.asImageの公式仕様](https://www.espruino.com/ReferenceBANGLEJS2#l_Graphics_asImage)に基づき、取得画像の寸法も検証します。日の出・日の入りのBMP保存は従来どおり完全描画後に行います。

電池消費の実測はまだありません。5Hzによるサンプル数削減やピーク計算休止はCPU処理の削減であり、そのまま同じ割合の電池削減を意味しません。
